## 3. 详细测试结果

### 3.1 Q-018「修复错误」按钮（RT-18）

**根因复现**（Node REPL，修复前逻辑）：

```js
const result = { error: 'Traceback...\n  File "main.py", line 5\n    x = "y"\nNameError: name \'z\' is not defined' };
// 原代码：onclick="...msg:${JSON.stringify(result.error)}..."
// → JSON.stringify 产出的 " 会闭合 onclick="..." 属性，后续 JS 串到屏幕
```

**修复后验证**（Node REPL）：用 `JSON.stringify(JSON.stringify(error))` 生成 `errMsg` 赋值表达式，对含 `"`、`\n`、`'`、`\` 的复杂 traceback，`new Function(scriptBody)()` 正确执行无语法错误，`errMsg` 解析后长度正确（115 字符）。

**代码变更**：`apps/frontend/src/pages/Create.tsx` `buildExecutionResultHtml`
- 按钮去掉 `onclick` 属性，仅保留骨架
- 末尾追加 `<script>`，`getElementById('__ask_ai_btn')` 后 `btn.onclick = function(){...}` 绑定
- `postMessage` 的 msg 用局部变量 `errMsg` 传入

**RT-18 通过标准**：运行必报错代码 → 弹窗无 `onclick=(function(){...})` 文本 + 点按钮聊天框自动发出修复请求 + 错误含双引号也正常。✅（代码层已验证，待有头 E2E 联调确认）

### 3.2 Q-019 生成代码后编辑器空白（RT-19）

**根因复现**（代码审查）：

```
后端 tools.py:917-923  ToolResult.data = {project_id, language, filename, saved_at, code_length}
                                  ↑ 不含 code/files
后端 orchestrator.py:1015-1023  yield ("code_generated", {code, files, ...})  ← 权威数据，但...
前端 useStreamingChat.ts  无 type === 'code_generated' 分支  ← 整体忽略！
前端唯一读代码路径  tool_result 读 out.code/out.files = undefined  ← 因后端 tool 没返回
→ 编辑器永远空白
```

**修复后验证**：

1. **前端 `useStreamingChat.ts`**：新增 `if (type === 'code_generated' && data)` 分支（line ~748），读 `data.code/files/filename/project_id`，调 `events?.onCodeGenerated?.({...})`，复用 `codeEventFired` 防重复。
2. **后端 `tools.py` `ProjectCodeWriterTool`**：`ToolResult.data` 补 `"code": code` 和 `"files": updated_files`（line 917-923）。

**RT-19 通过标准**：推进到 stage_05/07/08 → AI 调 project_code_writer → 编辑器显示代码 + 文件区显示真实文件名 + 刷新后代码仍在。✅（前后端代码已改，数据流贯通；待 WS 联调确认）
