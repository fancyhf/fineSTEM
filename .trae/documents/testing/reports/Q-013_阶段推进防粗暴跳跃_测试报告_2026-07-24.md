## 五、失败分析

### 5.1 Token/API 连接失败类（非 Q-013 回归）

**影响范围**：`pbl-stage-progression.spec.ts`（7 fail）、`create-pbl-flow.spec.ts`（5 fail）、`pbl-question-card-full-test.spec.ts`（12 fail）

**根因**：这些 spec 使用 `helpers/api.ts` 中的 `createProject()` 函数，依赖硬编码的 `TEST_USER_TOKEN` 环境变量（默认值 `'test-token'`）。当后端未配置该测试 token 或后端服务不可达时，`POST /api/v1/projects` 返回非 200。

**证据**：所有失败的堆栈完全一致——都在 `helpers/api.ts:17` 的 `expect(response.ok()).toBe(true)` 处失败。

**结论**：❌ **不是 Q-013 回归**。这是测试基础设施问题（需要有效的 test token 或改用 fixtures 自动注册）。

### 5.2 超时类（非 Q-013 回归）

**影响范围**：`mvp-bug-e2e.spec.ts`（1 fail — 30s 超时）、`project-detail-generate-achievement.spec.ts`（1 fail — 10s API 超时）

**结论**：⚠️ **不是 Q-013 回归**。超时配置偏短或网络延迟。

### 5.3 AI 文本变化类（非 Q-013 回归）

**影响范围**：`create-guided-pbl-mainline.spec.ts`（1 fail — 第三问期望文本 "你有初步想法了吗？" 但实际显示的是第二问文本）

**结论**：⚠️ **不是 Q-013 回归**。AI 回复的内容/顺序有随机性，测试断言过于精确。

### 5.4 数据水合类（需关注）

**影响范围**：`project-detail-stage08-hydration.spec.ts`（1 fail — textarea 回填为空）

**结论**：⚠️ **低风险**。可能是数据写入时机或前端水合逻辑的问题，但不影响 Q-013 门禁功能。
