# 流式卡死 + 续接回到 Step1 回归测试任务（Q-023 新增）

你是测试 agent。对 fineSTEM AI 对话系统执行回归测试，重点验证 Q-023 修复：流式输出吐字到一半卡死时不再干等转圈 + 续接时能从断点接着写（不回 Step1）。

## 本次变更（2026-07-29）

**Q-023**（两个独立子问题，项目 `8a7c155e` 截图实证）：
- **子问题 A（卡死转圈）**：AI 讲解式模式生成 Step2 词库代码，输出到"词库 ="卡住，三个点一直转（无止境转圈）
- **子问题 B（续接回到 Step1）**：用户点"继续生成"后，AI 没从"词库 ="接着写，而是回到 Step1 从头讲

**关键架构事实**：前端直连 ZeroClaw daemon（闭源 Rust），daemon 内部超时不可控——本次修复全在前端。

**修复方案**：
- **A（空闲超时）**：`useStreamingChat.ts` 加 `idleTimer`——收到首个 chunk 后启动 30s 计时，每来新 chunk 重置；30s 无新内容→判定卡死→保留已生成内容（不丢"词库 ="）+ 显示"继续生成"按钮（非 reject 抛错、非干等 120s）
- **B（续接带上文）**：自动续接 + 手动"继续生成"的消息里显式拼入上一轮已输出内容（末尾 2000 字，包在 `<previous_output>` 标签），AI 能看到断点从"词库 ="接着写

### 步骤 2：核心 E2E —— 流式卡死保留内容（TC-DLG-031 / Q-023A）

**目标**：验证流式吐字到一半卡住时，30s 内保留已生成内容 + 显示继续按钮。

**难点**：卡死是偶发的（取决于 daemon/LLM 状态），真实复现可能要等多轮。两种测法：

**方式 1（真实等待，推荐）**：
1. 进入 Create 页，推进到 stage_07（讲解式 lecture 模式）
2. 让 AI 生成大段代码（发"请完整实现所有功能代码，用讲解式逐步讲解每一步"）
3. 观察 AI 流式输出——如果输出到一半停住（三个点转超过 30s 不出新内容）
4. **检查点 A1**：30s 后聊天气泡**保留**已生成的部分内容（如"词库 ="那段不丢）
5. **检查点 A2**：显示"继续生成"按钮（不是干等到 120s 报超时）
6. **检查点 A3**：控制台有 `[useStreamingChat] chunk 空闲超时（30s 无新内容）` 日志

**方式 2（如果真实对话没卡死，用 Network throttle 模拟）**：
- Playwright 模拟慢网络（`page.context().setOffline(false)` + throttle），或直接观察正常对话确认 idleTimer 不误触发

**证据**：卡死时的聊天气泡截图（保留部分内容）+ 控制台空闲超时日志截图。

---

### 步骤 3：核心 E2E —— 续接从断点接着写（TC-DLG-032 / Q-023B）

**目标**：验证点"继续生成"后 AI 从断点接着写，不回 Step1。

1. 承接步骤 2（如果发生了卡死），或手动制造截断（发"请只输出前半部分代码"→ 再点继续）
2. 点"继续生成"按钮
3. **检查点 B1**：AI 的新输出**从断点接着写**（如接着"词库 ="后面写 `= [...]`），**不是**回到 Step1 重新讲原理
4. **检查点 B2**（用 WS 抓帧或控制台）：续接发给 daemon 的消息里含 `<previous_output>...词库 =...</previous_output>`
5. **检查点 B3**：续接内容与前文格式连贯（代码块正确闭合、无突兀的"好的我继续"过渡语）

**对照（修复前 vs 修复后）**：
- ❌ 修复前：点继续 → AI 说"好的，我们从头开始讲解" → 回到 Step1
- ✅ 修复后：点继续 → AI 接着"词库 ="写下去

**证据**：续接前后聊天记录截图（显示从断点接续）+ WS 消息含 previous_output 的证据。

### 步骤 4：回归（不能退化）

| 回归项 | 验证方法 | 通过标准 |
|--------|---------|---------|
| **正常短对话不误判卡死** | 发"你好"/简单问答 | 正常秒回，不会 30s 后误显示"继续生成"（idleTimer 收到 done 帧会清除） |
| **正常长回复不中断** | AI 正常生成完整长回复（未卡死） | 完整输出，不被 idleTimer 截断（只要持续有 chunk，timer 一直重置） |
| **自动续接仍生效** | finish_reason=length 截断时 | 自动续接 2 次内完成（带 previous_output 上文） |
| **其他功能不退化** | 选项卡/代码生成/项目名 | 正常工作 |

**判定标准**：
- A/B 任一 ❌ → 整体不通过，状态改回 🔴
- **重要**：如果真实对话一直没卡死（daemon 稳定），A 可以标注"未触发，待偶发复现时验证"，重点测 B（续接带上文，这个每次都能测）

特别说明：
- **卡死是偶发的**——取决于 daemon/DeepSeek 状态。如果本次测试没复现卡死，A 项记录"未触发"，不要硬造
- **B 项每次都能测**——即使没卡死，也可发"请只输出代码的前半部分"人为制造截断，再点继续验证接续
- idleTimer 的 30s 阈值：正常 DeepSeek 流式每秒都有 chunk，30s 无新内容几乎一定是卡死
