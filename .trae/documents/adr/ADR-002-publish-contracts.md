# ADR-002: 发布契约 —— 生产工作区与发布平台分离

- **状态**: Accepted
- **日期**: 2026-08-24
- **决策者**: AI Agent + 项目负责人
- **背景讨论**: 多个小任务/内容项目分散在不同工作空间（G:\mediaProjects、G:\buddyspace 等），技术方案各异（手写 HTML 动画、视频生产流水线、Web 应用），如何接入部署而不失控
- **links**: `deploy/Know子系统部署指南_v1.0.md`（契约①②的落地实现），`governance/domain-and-dns-policy.md`（域名与部署登记），ADR-001（服务器与域名底座）

---

## 1. 背景与上下文

现状：内容生产分散在多个工作空间，各有自己的技术栈——鸡娃先自鸡的互动动画是手写独立 HTML，视频在 B 站，脚本/策划是 markdown；fineSTEM 是正经 web 平台。未来还会有新内容、新小系统。

两个失败路线：强行统一技术（扼杀创作效率）或每个项目自建部署（运维爆炸）。

## 2. 决策

**不统一技术方案，统一"上线方式"。** 生产（各工作空间随便做）与发布（平台窄口）分离。平台只支持三种接入契约：

| 契约 | 适用 | 接入方式 | 现有实现 |
|------|------|---------|---------|
| **① 静态资源型** | 动画 HTML、文档、图片、音频、任何"产物是文件"的东西 | 复制进 `content/know/`，写 JSON 清单（episode.json），`npm run validate:content` 校验通过后 rsync 上服务器即生效 | Know 频道内容库（content-as-code） |
| **② 独立 Web 应用型** | 有自己交互逻辑的小系统 | monorepo `apps/xxx` 或独立仓库 → 构建 `dist/` → 分配子域名 + nginx server block | Know 频道前端（apps/know） |
| **③ 后端能力型** | 真需要服务端逻辑的 | 优先做现有 FastAPI 进程里的只读路由；带状态/重计算的不在此列 | `/api/v1/know/*` 五个只读接口 |

### 关键原则

1. **视频一律 B 站嵌入，服务器不存视频**。平台只做成果展示（embed + 链接），不承担视频存储与带宽。资源模型里每条视频独立条目（embed_url），换平台只改数据。
2. **契约①的产物不感知平台**：动画保持手写 HTML 原样托管（iframe 嵌入），平台不要求改写为任何框架组件。字体等公共资源由平台提供（自托管 @fontsource，禁外部 CDN）。
3. **一切部署所需必须进 git 仓库**（代码+内容+说明文档）。理由：云服务器只能方便地从 GitHub 取东西，工作空间在本地不可达；因此"搬运入库 + commit + push"是发布的必经环节，服务器侧只做 git pull。唯一例外：视频不进仓库——一律 B 站链接形态存于 episode.json（原则 1）。
4. **反向规则（垃圾抽屉防线）**：这台 2C2G 服务器不接收带重计算（视频转码/AI 训练）、大数据库、自有用户体系的任务。这类任务在别处完成，以契约①静态产物形态出现。
4. **新任务决策树**：给观众看的内容 → 契约①；给用户的独立功能系统 → 契约②（评估进 monorepo 还是独立 app）；自己用的实验 → 留在工作空间不上线。

## 3. 搬运流程（Import SOP，2026-08-24 补）

日常工作模式：内容与开发在各工作空间完成 → **负责人告知 Agent 源路径** → Agent 执行：

1. 互动 web 代码 → `content/know/series/<系列>/<集>/interactive/`（原样复制不改写）
2. 说明文档 → 同集 `docs/`；填 `episode.json`（B 站视频链接由负责人后续提供再补 embed_url）
3. `npm run validate:content` 零错误 → `git commit` + `git push`
4. 服务器 `git pull` 即生效（内容按文件指纹缓存自动失效；前端改动需在服务器 `npm run build:know`）

详细命令见 `deploy/Know子系统部署指南_v1.0.md` §2。

---

## 4. 后果

- 正面：创作工作区零约束；上线只有改 nginx + DNS 一个审批口；台账清晰（见 governance 登记表）
- 代价：每种契约要维护一个校验脚本（现有 `validate:content`）；契约③超阈值时需另起进程/服务器（当时再评估）

**ADR 结束**
