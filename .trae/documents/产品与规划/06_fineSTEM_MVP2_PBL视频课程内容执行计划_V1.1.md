## 0. 计划目标

本计划用于完成第一个“项目、视频、课程、平台体验、成果展示”一体化样板。

本文件是三大任务总体计划中的 **T3内容执行子计划**。域名与云端发布、MVP2代码开发及三项任务的统一排期，见《07_fineSTEM_MVP2_三大任务总体执行计划_V1.0.md》。

首个样板：

> **AI+古诗：做一套会搜索的知识卡**

本计划不负责外部视频平台营销、播放数据、渠道归因或社群维护，只负责：

- 如何从一个fineSTEM PBL项目规划视频内容
- 如何把视频组织成课程
- 如何让课程与项目实验室相互衔接
- 如何让孩子独立完成
- 如何让家长看懂成果
- 如何形成下一项目可复制模板

首个样板必须同时跑通两条工作线：

| 工作线 | 目标 | 核心交付 |
|--------|------|----------|
| A线：代码与产品 | 让fineSTEM能够承载、编排和调用项目课程与公共知识胶囊 | 项目实验室、课程/课时、跨项目课时映射、B站嵌入、工作台推荐、家长成果 |
| B线：内容与视频 | 完成首批5条学生视频并发布到B站 | 脚本、分镜、正式素材、动画、字幕、封面、视频地址、文字摘要 |

最终验收对象不是两条线各自的产物，而是一条完整路径：

```text
试玩Demo
→ 进入项目实验室
→ 按当前需要观看项目课时或公共知识胶囊
→ Fork并修改自己的项目
→ 使用AI理解和调试
→ 验证并生成成果
→ 家长看懂成果
```

## 1. 内容设计总原则

### 1.1 项目先于课程

先确定孩子要做出什么，再决定需要拍什么视频。

错误顺序：

```text
先想拍哪些编程知识
→ 再寻找一个项目套进去
```

正确顺序：

```text
确定项目成果
→ 拆出孩子必须完成的行动
→ 找出可能卡住的知识和操作
→ 为这些节点制作短视频
```

### 1.2 每条视频都服务一个行动

视频看完以后，孩子应立即能做一件事：

- 选择一个项目变体
- 修改一组数据
- 调整一个参数
- 增加一个小功能
- 读懂一条错误
- 验证一次结果
- 解释自己的改动

不制作只有概念、没有项目动作出口的长视频。

### 1.3 视频不是必修门禁

- 孩子可以直接从Demo进入项目实验室。
- 已经会的内容可以跳过。
- 卡住时可以回看对应课时。
- 课程是支架，不是必须按顺序看完的作业。

### 1.4 一个视频只解决一个主要问题

推荐时长：

| 类型 | 时长 |
|------|------|
| 项目效果/兴趣视频 | 30-90秒 |
| 项目步骤视频 | 3-6分钟 |
| 知识胶囊 | 2-5分钟 |
| AI协作/调试 | 2-5分钟 |
| 家长说明 | 1-3分钟 |

复杂操作拆成多条，不用一条20分钟视频覆盖完整项目。

### 1.5 内容必须与正式产品一致

- 视频使用正式项目模板和正式页面录制。
- 按钮名称与系统一致。
- 不展示已经删除或尚未实现的功能。
- 不用剪辑制造系统不存在的即时效果。
- 视频发布后产品发生变化时，更新文字说明或重新录制关键步骤。

## 2. 一套PBL项目的内容结构

每个成熟项目应沉淀为五层内容。

### 2.1 第一层：项目效果视频

目的：让孩子快速判断“我想不想做”。

内容：

- 最终作品真实运行
- 2-3个可修改点
- 孩子最终会得到什么
- 进入项目实验室的提示

不讲完整过程，不解释大量技术名词。

### 2.2 第二层：项目课程

目的：陪孩子完成一个轻项目。

通常由4-6节组成：

1. 看懂项目和选择方向
2. 完成第一次有效修改
3. 理解一个核心原理
4. 增加个人化功能
5. 调试和验证
6. 解释并生成成果

### 2.3 第三层：知识胶囊

目的：在项目需要时补充一个编程或STEM概念。

示例：

- 变量和参数
- 数组与对象
- 条件判断
- 状态与事件
- 数据可视化
- 坐标和函数
- 测试与对照实验

知识胶囊可以被多个项目复用。

### 2.4 第四层：AI协作胶囊

目的：让孩子获得掌控感，而不是把项目全部交给AI。

固定主题：

- 怎样把想法描述清楚
- 怎样让AI只改一个功能
- 怎样让AI解释代码而不是重写全部
- 怎样把错误信息交给AI
- 怎样检查AI给出的结果
- 怎样说明哪些决定是自己做的

### 2.5 第五层：家长说明

目的：家长不看代码，也能理解项目过程和成果。

内容：

- 孩子会做出什么
- 孩子必须亲自完成哪些动作
- AI会在哪些地方提供帮助
- 家长可以问的三个问题
- 怎样阅读成果档案卡

### 2.6 公共知识课程的三条主线

公共知识课不先做成几十节的大而全体系，而是在每个样板项目中新增1-2个真正用得上的胶囊。胶囊先服务当前项目，再通过fineSTEM的课时映射被后续项目复用。

#### 编程基础：程序怎样保存和改变信息

| 建设批次 | 知识胶囊 | 项目中的具体问题 |
|----------|----------|------------------|
| 首批 | 变量与参数 | 为什么改一个值就能改变标题、颜色或速度 |
| 首批 | 数组与对象 | 多张卡片的数据放在哪里，页面怎样读取它们 |
| 第二批 | 条件判断 | 搜索、筛选和答题结果怎样决定显示什么 |
| 第二批 | 循环与函数 | 相似步骤怎样重复，功能怎样封装后再次使用 |
| 第三批 | 事件与状态 | 点击、输入和收藏为什么会改变页面 |
| 第三批 | 本地存储与API | 数据怎样保留，程序怎样获取外部信息 |

#### 算法思维：把问题变成可以执行的步骤

| 建设批次 | 知识胶囊 | 项目中的具体问题 |
|----------|----------|------------------|
| 首批 | 问题分解 | 一个项目怎样拆成输入、处理、输出和验证 |
| 首批 | 搜索与筛选 | 程序怎样从多条数据中找到符合条件的内容 |
| 第二批 | 排序与计分规则 | 列表顺序、排行榜和测验分数怎样计算 |
| 第二批 | 随机与模拟 | 随机抽题、概率实验和多次试验意味着什么 |
| 第三批 | 复杂度直觉 | 数据变多后，为什么有的方法会明显变慢 |

#### AI素养：理解AI并保持人的判断

| 建设批次 | 知识胶囊 | 项目中的具体问题 |
|----------|----------|------------------|
| 首批 | 输入-模型-输出 | AI收到什么、处理什么、返回什么 |
| 首批 | 让AI解释第一条错误 | 怎样提供错误、上下文和期望结果 |
| 首批 | 结果核验 | 为什么AI给了答案仍需要运行和检查 |
| 第二批 | 幻觉与证据 | 知识内容和引用怎样核对 |
| 第二批 | 训练与推理 | AI“学习过”和当前“生成答案”有什么区别 |
| 第三批 | 隐私、偏差与边界 | 哪些信息不该输入，模型结果可能偏在哪里 |

公共胶囊的最低内容结构：

```text
一个项目中的真实问题
→ 一个可视化解释
→ 一个最小例子
→ 回到项目完成一次操作
→ 一个自查问题
```

它们不是传统意义上先修完才能做项目的“基础课”，而是随项目出现、可以反复调用的公共能力层。

## 3. PBL阶段与视频规划模板

### 3.1 轻项目3步模板

| 项目步骤 | 学生行动 | 视频主题 | 平台出口 |
|----------|----------|----------|----------|
| Step 1 想法与方向 | 看成品、选择变体、确定最低目标 | 成品展示、变体案例、范围选择 | 选择挑战并创建项目 |
| Step 2 设计与实现 | 修改、运行、调试、增加功能 | 操作演示、核心原理、AI调试 | 返回工作台继续修改 |
| Step 3 展示与反思 | 测试、截图、说明、生成成果 | 验收方法、反思示例、成果卡 | 生成并分享成果 |

### 3.2 标准9阶段模板

| 阶段 | 课程内容问题 | 推荐内容形态 |
|------|--------------|--------------|
| stage_00 初始化 | 项目从哪里开始？ | 入口说明，通常不单独拍视频 |
| stage_01 脑爆 | 这个项目还能变成什么？ | 变体案例短片 |
| stage_02 开题 | 我要为谁解决什么问题？ | 目标选择示范 |
| stage_03 范围 | 第一版只做什么？ | MVP裁剪胶囊 |
| stage_04 轨道 | 有哪些实现方式？ | 技术路线比较 |
| stage_05 设计 | 数据、页面和交互怎样组织？ | 草图和结构拆解 |
| stage_06 计划 | 怎样拆成几步完成？ | 执行清单示范 |
| stage_07 执行 | 怎样实现、调试和改进？ | 多条操作与知识胶囊 |
| stage_08 验收 | 怎样证明它完成了？ | 测试、解释、成果卡 |

轻项目课程不必机械对应9个阶段。标准研学时，系统再把轻项目内容映射到完整阶段。

### 3.3 每条视频的标准脚本

```text
1. 先展示本节完成后的效果
2. 说明这一节只解决什么问题
3. 在正式项目中演示操作
4. 用一句话解释背后的原理
5. 展示一次运行或检查
6. 给出孩子现在要完成的动作
7. 返回项目实验室或工作台
```

视频结尾不是“记得点赞关注”，而是明确项目动作，例如：

> 现在回到项目实验室，选择“轻松改”，把第一张卡片换成你自己的内容。

外部平台可以保留常规账号提示，但fineSTEM课程版本的核心出口始终是项目动作。

## 4. 首个项目内容设计

### 4.1 项目定义

| 项目 | 内容 |
|------|------|
| Demo | 文学知识卡 `demo_poetry_card` |
| 项目实验室 | 我的古诗知识卡 |
| 项目课程 | AI+古诗：做一套会搜索的知识卡 |
| 年龄 | 12-15岁 |
| 轻项目时长 | 45-90分钟 |
| 前置知识 | 无 |
| 最低成果 | 自定义知识卡、成功运行、截图、反思、成果档案卡 |

### 4.2 项目学习目标

学生完成后能够：

- 把多条诗词或知识整理成结构化数据。
- 修改标题、内容和页面主题。
- 理解“数据变化会让页面显示变化”。
- 体验搜索或收藏这样的交互功能。
- 使用AI解释错误或一个关键代码片段。
- 用自己的话说明改动和验证结果。

不承诺：

- 掌握完整HTML/CSS/JavaScript体系
- 独立从零开发复杂网站
- 完成后显著提高语文成绩

### 4.3 三档挑战

| 挑战 | 任务 | 最低验收 |
|------|------|----------|
| 轻松改 | 替换2首诗、修改标题和主题颜色 | 页面显示自己的内容并成功运行 |
| 进阶改 | 增加分类、搜索字段或收藏筛选 | 新功能重复操作有效 |
| 创意改 | 增加随机抽卡、背诵提示或小测验 | 有输入、处理和反馈闭环 |

### 4.4 MVP2首批学生视频与内容归属

首批先制作5条，不要求一次制作完整扩展课程。

| 编号 | 课时名称 | 时长 | 内容归属 | 对应PBL | 看完要做什么 |
|------|----------|------|----------|---------|--------------|
| V01 | 这套古诗卡片是怎样做出来的 | 1-2分钟 | 古诗项目专属 | Step 1 | 试玩Demo并选择挑战 |
| V02 | 只改三处，变成你的知识卡 | 4-6分钟 | 古诗项目专属 | Step 2 | 修改标题、诗词和颜色 |
| V03 | 数组：数据怎样变成一张张网页卡片 | 3-5分钟 | 公共编程胶囊 | Step 2 | 找到并修改数组中的一条数据 |
| V04 | 让AI帮你看懂第一条错误 | 3-5分钟 | 公共AI胶囊 | Step 2 | 用AI解释一个错误并再次运行、核验结果 |
| V05 | 怎样证明这是你完成的项目 | 3-5分钟 | 古诗项目专属 | Step 3 | 截图、写反思、生成成果卡 |

课程与实验室的编排关系：

```text
古诗项目课程：V01 + V02 + V05
公共编程课程：V03
公共AI课程：V04

“我的古诗知识卡”项目实验室学习路径：V01 -> V02 -> V03 -> V04 -> V05
```

V03和V04只保存一份内容。后续项目通过课时映射引用，不重新上传同题视频。项目课程详情把它们展示为“本项目会用到的公共知识”，项目实验室和工作台按当前阶段推荐。

P1扩展课时：

| 编号 | 课时名称 | 作用 |
|------|----------|------|
| V06 | 收藏按钮为什么会变成星星 | 解释状态和事件 |
| V07 | 给知识卡加一个随机抽题 | 创意挑战实现 |
| V08 | 从古诗卡变成历史人物卡 | 展示跨学科复用 |

### 4.5 视频视觉与制作模式

不同内容应使用不同表达方式，不把所有课都做成录屏，也不把所有概念都做成高成本数学动画。

| 内容类型 | 推荐模式 | 适合内容 | 不建议 |
|----------|----------|----------|--------|
| 项目认识与操作 | 真实屏幕录制 + 局部放大 + 箭头/高亮标注 | V01、V02、V05，平台入口和实际操作 | 用动画模拟不存在的产品界面 |
| 编程概念 | 代码追踪 + 数据流/状态变化的二维动画 | 数组、条件、循环、事件、状态 | 长时间逐行朗读代码 |
| 算法概念 | 卡片、节点或图形的逐步状态变化 | 搜索、排序、计分、随机、模拟 | 只讲定义和术语 |
| 数学与科学模型 | 选择性使用3Blue1Brown/Manim式连续可视化 | 函数、坐标、运动、概率等空间关系强的主题 | 普通按钮操作也制作重动画 |
| AI知识与协作 | 输入-模型-输出动画 + 一次真实交互 + 结果核验 | 提示、报错解释、幻觉、隐私和偏差 | 把AI表现成会思考的人物角色 |
| 家长说明 | 简洁信息图 + 成果证据逐项讲解 | 改动、运行、解释、反思和AI边界 | 教家长代码语法 |

首阶段建议的制作投入比例：

- 约60%使用真实屏幕录制、光标强调、局部放大和字幕。
- 约30%使用可复用的二维矢量动画模板，重点服务编程、算法和AI概念。
- 约10%用于旗舰概念的连续数学动画，只有内容确实依赖空间变化时才使用。

首批5条的具体形式：

| 视频 | 主画面 | 辅助表达 |
|------|--------|----------|
| V01 | Demo真实运行和三个变体快速切换 | 简短标题动画，不讲代码 |
| V02 | fineSTEM正式工作台录屏 | 三处改动编号、前后对比、运行结果 |
| V03 | 数据数组到卡片界面的数据流动画 | 只截取最小代码片段并逐步高亮 |
| V04 | 一次真实报错、AI解释和重新运行 | 输入-上下文-建议-核验四步系统图 |
| V05 | 截图、反思和成果卡生成录屏 | 用证据标记区分“做过”与“看过” |

为了形成稳定风格，先建立一套公共视觉组件：代码框、数据卡片、流程箭头、状态标签、错误提示、AI输入/输出框和成果证据标记。后续项目只换内容，不重新设计整套动画语言。

### 4.6 家长内容

首批制作一条家长视频或图文说明：

> 《不懂编程，怎样判断孩子不是让AI代做》

结构：

1. 看孩子是否改变了项目内容和目标。
2. 看孩子是否亲自运行和修复过问题。
3. 让孩子解释一个关键原理。
4. 看成果卡是否包含截图、改动和反思。
5. 问清楚AI做了什么、孩子决定了什么。

这条内容既可以发布到第三方平台，也必须在项目实验室家长说明区提供文字版。

## 5. 课程页面编排

### 5.1 课程列表卡片

- 真实知识卡截图
- “把课本内容做成可搜索、可收藏的网页卡片”
- 12-15岁
- 5段学习内容（3条项目专属课时 + 2条公共知识胶囊）

- 主动作：查看课程

### 5.2 课程详情顺序

```text
课程介绍
→ V01 项目总览
→ 进入项目实验室
→ V02 第一次修改
→ 本项目会用到的公共知识：V03 数组
→ 卡住时使用：V04 AI调试
→ V05 成果展示
→ 示例成果卡
```

用户不必按顺序看完。课程详情中“进入项目实验室”应始终可见。V03和V04以关联胶囊出现，不复制为古诗项目课程的私有课时。

### 5.3 项目工作台中的课时推荐

| 当前状态 | 推荐课时 |
|----------|----------|
| 项目刚创建 | V02 第一次修改 |
| 正在修改数据 | V03 数据与卡片 |
| 运行出错 | V04 AI调试 |
| 代码已运行 | V05 验收与成果 |

推荐只展示1-2条最相关内容，不展示整套播放列表干扰项目。

## 6. 内容生产SOP

### 6.1 选题门禁

一个项目进入视频课程制作前必须满足：

- 最终效果能在10秒内看懂。
- 有至少3个学生可修改点。
- 最低版本可在90分钟内完成。
- 首次使用不需要本地安装和个人API Key。
- 项目有稳定的最小可改版。
- 可以自动或半自动生成成果证据。
- 家长可以用非技术语言理解成果。

### 6.2 项目冻结

拍摄前冻结：

- Demo版本
- 最小模板
- 页面按钮文字
- 三档挑战
- 最低完成标准
- 主要截图
- 成果卡字段

冻结后只修阻塞问题，不在拍摄期间增加大功能。

### 6.3 内容拆解

逐步完成：

1. 写出孩子最终成果。
2. 写出从模板到成果的关键动作。
3. 标记每个动作可能卡住的位置。
4. 判断哪些问题由页面文字解决。
5. 判断哪些问题由AI解决。
6. 只为仍需视觉演示或概念解释的部分制作视频。

不是所有步骤都需要视频。

### 6.4 集中录制

一次性录制素材：

- 完整成品运行
- 第一次打开模板
- 修改标题、数据和颜色
- 搜索与收藏操作
- 一次真实报错
- 使用AI解释并修复
- 截图和成果卡生成
- 家长分享页

随后从同一批正式素材剪出不同课时，保证页面一致。

### 6.5 第三方发布与集成

发布到第三方平台后，录入：

- 平台类型
- 视频ID
- iframe嵌入地址
- 外部观看地址
- 封面
- 时长
- 文字摘要
- 字幕或文字稿
- 关联实验室
- 关联PBL步骤

不录入播放率、评论数、粉丝数和外部账号数据。

## 7. 双线执行与集成交接

### 7.1 A线：代码与产品

A线负责让平台真正承载内容和项目学习过程：

1. 复用现有登录、鉴权和项目归属，不重新建设用户系统。
2. 建立项目实验室及三档挑战。
3. 建立课程、课时和公开读取能力。
4. 建立 `LabLessonLink`，按项目阶段调用公共胶囊。
5. 建立B站安全嵌入、文字摘要和失效回退。
6. 在工作台按当前步骤推荐1-2条最相关课时。
7. 在成果分享页形成家长可理解的证据摘要。

### 7.2 B线：内容与视频

B线负责把首个项目做成可观看、可操作、可复用的内容：

1. 冻结项目目标、挑战、最低成果和正式操作路径。
2. 完成V01-V05脚本、分镜、旁白和字幕初稿。
3. 制作V03、V04所需的公共动画组件。
4. 在可录制版本上集中获取正式项目素材。
5. 完成剪辑、字幕、封面和文字摘要。
6. 上传B站并提交嵌入地址、外部地址和视频ID。
7. 回到fineSTEM检查视频与每个项目动作是否一致。

### 7.3 四个集成交接门

| 交接门 | A线必须完成 | B线必须完成 | 通过标准 |
|--------|-------------|-------------|----------|
| Gate 1 内容契约冻结 | 路由、按钮文案、挑战、课时字段、成果字段确定 | 5条脚本和镜头清单完成 | 每个镜头能对应正式页面或公共动画 |
| Gate 2 可录制版本 | Demo到成果主路径可运行，录屏页面不再改结构 | 旁白、分镜、动画模板就绪 | 可一次性录制正式屏幕素材 |
| Gate 3 视频回填 | 课程详情、嵌入回退、课时映射可用 | 5条视频已发布，封面/字幕/摘要齐全 | 项目实验室和工作台能打开正确视频 |
| Gate 4 自助盲走 | 阻塞问题修复，登录恢复和项目继续可靠 | 过时步骤修正，文字替代完整 | 不依赖运营者辅导完成项目并生成成果 |

关键依赖：

- B线现在就可以开始写脚本、画分镜、制作V03/V04动画，不必等待全部代码完成。
- 最终屏幕录制必须等Gate 1和Gate 2，否则界面改动会造成返工。
- A线可以用占位课时和测试视频完成课程集成，不必等待B站正式发布。
- Gate 3以后只按完整用户路径验收，不分别宣布“代码完成”或“视频完成”。

## 8. 八周双线执行计划

| 周次 | A线：代码与产品 | B线：内容与视频 | 本周交付/门禁 |
|------|----------------|----------------|---------------|
| 第1周 | 盘点现有Demo、Fork、登录恢复、成果卡能力；确定新增数据字段和路由 | 完整体验古诗Demo；确定三档挑战、最低成果、5条视频选题和家长说明 | 项目内容基线、差距清单 |
| 第2周 | 完成ProjectLab模型/API、实验室页、Demo入口和创建/继续项目 | 完成V01-V05脚本、旁白、分镜和镜头清单 | Gate 1：内容契约冻结 |
| 第3周 | 完成Course、CourseLesson、LabLessonLink、课程库公开读取和嵌入组件 | 制作统一视觉模板；优先完成V03数据流和V04 AI系统图动画初稿 | 可录入占位课时的课程框架 |
| 第4周 | 跑通Demo到成果路径，修复录屏阻塞问题，冻结正式页面结构 | 在正式版本集中录制Demo、修改、报错、AI调试、成果生成素材 | Gate 2：可录制版本与正式素材 |
| 第5周 | 完成工作台课时推荐、登录上下文恢复回归和家长成果摘要 | 剪辑V01-V05，完成字幕、封面、文字稿和项目动作检查 | 5条待发布成片 |
| 第6周 | 建立正式课程数据和课时映射，完成B站嵌入及失败回退联调 | 上传B站，提交视频ID、嵌入地址、外部地址、封面、摘要和字幕 | Gate 3：视频回填联调 |
| 第7周 | 修复自助流程、移动端阅读、视频失效和重复创建问题 | 根据盲走结果修正说明、字幕或必要镜头 | Gate 4：零辅导盲走通过 |
| 第8周 | 发布首个项目实验室和课程；整理代码配置与管理模板 | 发布示例成果和内容复用清单；确定第二项目复用V03/V04的方式 | MVP2首个完整样板 |

盲走验证不要求运营者直接辅导孩子。可以由内部人员按零基础路径测试，或由家长、教师转交链接后通过结构化问题收集反馈。

必须验证：

- 不看视频能否开始。
- 看视频后能否找到正确操作。
- 视频失效能否继续项目。
- AI首条引导是否具体。
- 最低完成标准是否过大。
- 成果卡是否有真实证据。
- 家长能否用自己的话复述孩子做了什么。

## 9. 内容质量门禁

### 8.1 学生内容

- [ ] 每条视频只解决一个主要问题
- [ ] 开头先展示结果
- [ ] 视频使用正式页面和模板
- [ ] 结尾有明确项目动作
- [ ] 不要求看完整套视频才能开始
- [ ] 不长时间朗读代码
- [ ] 不把AI生成等同于学生完成

### 8.2 项目内容

- [ ] 三档挑战都可实际完成
- [ ] 轻松改不超过30分钟核心操作
- [ ] 最低版本不依赖付费账号或API Key
- [ ] 有固定自查和错误处理说明
- [ ] 有截图、运行或文档证据
- [ ] 能生成成果档案卡

### 8.3 家长内容

- [ ] 不要求家长理解代码语法
- [ ] 不使用提分、竞赛和升学承诺
- [ ] 说明AI帮助与学生决定的区别
- [ ] 提供三个可直接提问的问题
- [ ] 分享页不暴露学生隐私

### 8.4 视频集成

- [ ] 第三方嵌入地址来自允许列表
- [ ] 有封面和加载状态
- [ ] 有文字摘要
- [ ] 关键视频有字幕或文字稿
- [ ] 嵌入失败可跳外部平台
- [ ] 视频失效不阻断项目

## 10. 下一批内容规划方法

### 9.1 项目选择评分

每项0-2分，总分至少10分才进入制作：

| 维度 | 判断 |
|------|------|
| 结果直观 | 10秒内能否看懂成品 |
| 可改造性 | 是否至少有3个明显修改点 |
| 自助性 | 是否不依赖人工教师 |
| 技术门槛 | 首次是否免安装、免API Key |
| PBL价值 | 是否有目标、设计、实现、验证和反思 |
| 家长可理解 | 是否能用非技术语言描述成果 |
| 内容复用 | 是否能产生可复用知识胶囊 |

### 9.2 推荐的内容序列

首个样板完成后，不立即扩大量课程，按不同项目价值验证：

1. 文学知识卡：学科融合与内容表达
2. 智能待办清单：生活工具与规则算法
3. 抛物线或自由落体实验：数学物理建模
4. 数据调查可视化：数据分析与社会观察
5. 家乡文化互动项目：本地知识与创意表达

每完成一个新项目，优先复用旧知识胶囊，而不是重新讲一遍相同编程概念。

## 11. 完成定义

首个内容计划完成必须同时具备：

- 一个正式项目实验室
- 一个稳定最小项目模板
- 三档挑战
- 一门项目课程
- 至少五条学生短视频课时
- 一份家长说明
- 工作台中的相关课时支架
- 一张家长可理解的成果档案卡
- 一套第二项目可复制的内容模板

播放量、完播率、粉丝量和课程销售均不属于本计划的完成条件。
