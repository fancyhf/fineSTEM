## 一、需求背景与目标

### 1.1 问题
学生在「创造」工作台与 AI 探讨代码原理时，AI 产出的**成体系讲解（核心原理 / 设计思路 / 关键代码拆解）只在聊天气泡里一次性流过**，关闭会话或刷新后无法回顾。缺乏一个"可沉淀、可回放"的讲解载体，学生想复习某段讲解只能重新问一遍 AI。

### 1.2 目标
新增第 9 种工件 **explanation（讲解文档）**，把 AI 的讲解要点**按时间戳章节累加**沉淀为一份项目级文档，并在四个入口（创建页气泡 / 创建页工具栏 / 项目详情 / Demo 详情）可读、可写、可回放。

### 1.3 非目标（明确不做）
- 不做多文档 / 版本树：讲解文档是项目内**单文档累加**。
- 不做逐条消息回放器：「回放」以分章节时间戳文档形式满足，不做消息级回放。
- 不把个人讲解写回共享 Demo 记录（Demo 全局共享，避免串数据）。

## 二、功能范围（四入口 + 双沉淀通路）

### 2.1 沉淀通路（写入讲解文档）

| 通路 | 触发方 | 行为 |
|---|---|---|
| ① 学生主动保存 | 创建页 AI 讲解气泡尾部「保存为讲解」按钮 | 把该条 AI 消息（>200 字）作为一章节追加 |
| ② AI 自动沉淀 | AI 完成一次成体系讲解后调用 `artifact_writer(artifact_name="explanation")` | 默认 append（防覆盖累加内容）；走 Q-038 scene_instructions 注入链路，daemon 无需重启 |

闲聊问答**不沉淀**（提示词约束：仅原理/设计/代码拆解类讲解才调 artifact_writer）。

### 2.2 四个展示入口

| 入口 | 位置 | 数据来源 | 操作 |
|---|---|---|---|
| A 创建页气泡 | AI 长消息尾部按钮 | — | 点击 → appendExplanation |
| B 创建页工具栏 | 页签工具栏「AI 讲解」按钮 | — | 把当前编辑器代码（截断 ~6000 字符）拼讲解提示词发进聊天流 |
| C 项目详情页 | 「讲解回顾」Card | `getDocument(id,'explanation')` | 查看讲解文档（弹窗）+「AI 讲解代码」按钮（进工作台自动发讲解提示词） |
| D Demo 详情页 | 四页签之一「讲解」 | 种子 `demo.explanation_doc` + 登录用户 fork 项目的讲解文档 | 查看种子讲解；登录用户额外见「我的讲解回顾」（只读自己 fork 的项目） |

## 三、核心语义规则

### 3.1 累加而非覆盖
每次沉淀以**带时间戳章节追加**到同一份 `standard_step_data.explanation_content`：

```
# 讲解文档

> 本文档由 AI 讲解沉淀而来，按时间累加，可随时回顾。

---

## 📖 {topic} · {YYYY-MM-DD HH:mm}

{content}
```

- topic 缺省取 content 首个 markdown 标题；无标题取首行截断 30 字。
- 同内容重复提交**跳过**（子串包含判重），防双击 / AI 重复调用产生重复章节。

### 3.2 不入阶段门禁
`explanation` **不进** `ARTIFACT_FOR_STAGE`（无 `ARTIFACT_TO_STAGE` 记录），靠 `artifact_stage_gate` 对"无阶段归属工件自动放行"实现**任意阶段可写、不影响阶段推进判定**。这是设计上的有意例外（非门禁遗漏）。

### 3.3 落盘
文件名 `08_code_explanation.md`，blob key `explanation_content`。底层复用 `pbl_engine.save_artifact`（落盘 + last_updated_at 维护）。

## 五、验收标准（功能级）

### 5.1 后端（已由 `.dbg/verify_explanation_api.py` 全链路验证通过）
1. ✅ POST 两次不同内容 → 均 `appended`，topic 正确（默认从标题推导 + 显式传入）
2. ✅ 重复内容 → `duplicate`（子串判重）
3. ✅ documents 列表含讲解文档（`08_code_explanation.md`）
4. ✅ 单文档含 N 个 `## 📖` 时间戳章节
5. ✅ artifact_writer 工具默认 append，重复 → duplicate
6. ✅ `mode=replace` 整篇覆盖（旧章节清空）
7. ✅ 种子 Demo `explanation_doc` 非空

### 5.2 前端（TC-16 覆盖）
1. 创建页 AI 长消息尾部出现「保存为讲解」按钮，点击后变「已保存 ✓」，重复点显「已在讲解文档中」
2. 保存后右侧文件树出现讲解文档（BookOpen 图标）
3. 项目详情页「讲解回顾」Card 显示段落数 + 摘要；点「查看讲解文档」弹窗展示全文
4. 创建页工具栏「AI 讲解」能把当前代码发进聊天流
5. Demo 详情「讲解」页签展示种子讲解内容；`?tab=explanation` 可直达
6. 登录用户从 Demo fork 的项目有讲解文档时，Demo「讲解」页签额外显示「我的讲解回顾」

## 七、假设与约束

1. 讲解文档为项目单文档累加（不做多文档 / 版本树）。
2. 「回放」以分章节时间戳文档形式满足，不做逐条消息回放器。
3. Demo「讲解」页签个人回顾只读自己 fork 的项目，不改共享 Demo 数据。
4. 迁移在 dev 启动时按既有 alembic 流程自动应用。
5. `explanation` 作为跨阶段工件刻意不进 `ARTIFACT_FOR_STAGE`——这是有意的设计例外，非门禁遗漏。
