## 0. 产品结论

MVP2不新增独立“项目实验室”页面，也不重做Create主界面。

现有主链路保持不变：

```text
Demo页签选择项目
-> 保存到我的项目
-> 项目详情
-> 进入代码编辑器
-> /create 恢复项目、代码和聊天
-> AI + Skill 协助修改、运行、验证和产出成果
```

MVP2只增加一层很薄的“复制项目任务引导”：

1. 仅当项目具有 `from_demo_id` 时启用。
2. 复制项目第一次进入Create时，显示一次非阻塞提醒。
3. 学生主动点击“开始任务引导”后，才触发AI，不自动发送对话。
4. 后续可从Create现有快捷区再次进入任务引导。
5. AI读取当前代码和Skill状态，只布置一项可修改、可运行、可验证的任务。
6. 学生自行创建的项目不显示提醒，也不注入这套流程。

数字人、AI朗读和语音输入统一放到MVP3，不进入MVP2开发和验收。

## 1. 代码现状审计

### 1.1 已经具备的能力

| 能力 | 当前实现 | MVP2处理 |
|------|----------|----------|
| 识别复制项目 | `Project.from_demo_id` 已存在，workspace响应会返回完整Project | 直接复用 |
| 恢复项目 | 项目详情通过 `finestem_restore_project` 进入Create，Create再读取workspace | 保持不变 |
| AI对话与问题卡 | Create已有流式对话、`QuestionCard` 和场景触发 | 直接复用 |
| 项目状态 | `SkillStateModel.skill_metadata` 已能保存教学模式和学生画像 | 增加很小的引导状态节点 |
| 教学模式 | 已有 `guided`、`demo`、`hands_on`、`lecture` 四种模式 | 不另建教学模式 |
| 代码读取与写入 | 后端已有 `project_code_reader`、`project_code_writer` | 引导启动时优先读取，不默认代写 |
| 运行与验证 | 已有编辑器运行、`code_runner`、预览和代码保存 | 作为“完成式”门禁 |
| 过程证据 | 已有 `evidence_saver` 和成果档案卡 | 任务通过后沉淀证据 |
| Demo任务素材 | 已有 `/demos/{demo_id}/fork-template`，返回模板、可修改点和建议 | 作为首批任务输入 |

### 1.2 Skill教学模式的真实边界

现有教学模式不是一个纯UI设置：

- 教学模式会写入Skill元数据。
- `stage_07_execute` 写代码前会检查学生是否确认了教学模式。
- Orchestrator目前只在 `stage_07` 和 `stage_08` 注入四种教学模式的提示规则。
- `hands_on` 已经具备“本轮任务 -> 验证标准 -> 常见报错 -> 必要提示”的完成式教学特征。

因此MVP2不应该再创造一套“AI导师模式”。

正确关系是：

```text
复制项目任务引导 = 什么时候开始、当前做哪一项任务、怎样判断完成
现有教学模式 = AI用什么方式教学生完成这项任务
现有Skill/PBL = 当前项目状态、阶段门禁、工件和证据的事实来源
```

### 1.3 当前最关键的两个代码缺口

#### 缺口A：保存Demo可能没有真正复制模板代码

当前前端“保存到我的项目”调用项目创建接口时，只传入项目名称、描述、`mode: light` 和 `from_demo_id`。后端创建项目时也只创建Project和空的SkillState，没有看到把Demo的 `minimal_replica` 或 `fork-template` 写入项目workspace的动作。

这意味着首个样板必须先验证：

```text
保存Demo后
-> 新项目workspace是否真的包含Demo代码和文件
```

如果workspace为空，MVP2开发的第一优先级不是引导弹窗，而是补齐“复制项目必须复制可修改代码”。否则学生进入Create后面对的是默认代码或空工作区，任务引导没有真实对象。

#### 缺口B：复制项目的轻项目模式与当前阶段可能不一致

Demo复制项目创建时使用 `mode: light`，但项目和SkillState的默认当前阶段仍可能是 `stage_01_brainstorm`。现有标准PBL代码门禁又会限制早期阶段的代码生成。

产品上，复制一个已经能运行的Demo，不应该重新经历完整的“从零选题”流程。它应被视为“改造型轻项目”：

```text
选择一个改造任务
-> 修改并运行
-> 解释改动并形成证据
```

开发前需要统一复制项目的Skill初始化规则，避免“界面让学生改代码，但AI被阶段门禁要求先重新选题”的冲突。

## 2. 适用范围

### 2.1 显示任务引导的项目

同时满足以下条件：

- 用户已登录并拥有项目。
- workspace返回的 `project.from_demo_id` 非空。
- 项目不是本地临时项目。
- Demo模板或项目workspace中存在可修改代码。

### 2.2 不显示任务引导的项目

- 学生从零创建的项目。
- 没有 `from_demo_id` 的历史项目。
- 只浏览Demo、尚未保存为自己项目的用户。
- workspace恢复失败的项目。

自己创建的项目继续使用现有AI对话、PBL阶段和教学模式，不增加首次提醒。

## 3. 用户流程

### 3.1 第一次进入复制项目

Create完成workspace恢复后，显示一次紧凑提醒：

```text
这是从Demo复制来的项目，你可以先运行看看，再完成一次自己的改造。
任务引导会一次只带你做一项修改，并在最后帮你检查是否真的完成。

[开始任务引导] [先自己看看]
以后可以从“任务引导”按钮再次进入。
```

交互规则：

- 提醒不遮挡整个Create，不强制学生开始。
- 不在提醒出现时自动向AI发送消息。
- “开始任务引导”会记录已开始并触发引导场景。
- “先自己看看”只关闭提醒，不隐藏后续入口。
- 同一项目换设备或重新登录后，不重复显示首次提醒。

### 3.2 再次进入

- 不重复弹首次提醒。
- Create现有“快捷”区域显示“任务引导”入口。
- 桌面端优先放入现有快捷区，避免额外悬浮层遮挡编辑器。
- 小屏或快捷区收起时，可以使用固定的小型图标按钮，并提供“任务引导”提示文字。

### 3.3 学生点击“开始任务引导”

系统向现有AI对话发送内部场景 `copy_project_guidance`，但对学生只显示自然语言结果。

AI必须按顺序完成：

1. 调用 `skill_state_reader` 读取项目模式、阶段和教学模式。
2. 调用 `project_code_reader` 读取当前真实文件，而不是根据Demo名称猜测。
3. 读取来源Demo的Fork模板、可修改点或首个样板配置。
4. 判断项目是否已有未完成任务或历史改动。
5. 只给一项任务、一个完成条件和一个下一步动作。

首轮回复示例：

```text
我已经看过这个知识卡项目。我们先完成第一次个性化：
把页面标题和第一张卡片换成你喜欢的内容，然后运行一次。

完成条件：页面能正常打开，并能看到你修改后的标题和卡片。

[带我找到要改的位置] [我先自己试试] [先讲讲数据在哪里]
```

## 4. “任务引导”和教学模式的协同

### 4.1 默认教学策略

复制项目的第一次改造默认采用“动手式”的行为原则：

- 先给任务和验证标准。
- 不先给完整答案。
- 学生卡住后再逐级给提示。
- 学生明确要求或多次失败后，才提供关键代码。

这不等于静默修改全局教学模式。Create仍保留现有四种模式切换，学生选择后继续使用已持久化的模式。

### 4.2 四种模式在复制项目中的表现

| 模式 | 引导表现 |
|------|----------|
| 引导式 `guided` | 指出文件和位置，给骨架或TODO，让学生补关键内容 |
| 演示式 `demo` | 先展示一次完整改法，再让学生换成自己的内容 |
| 动手式 `hands_on` | 只给任务、完成条件和提示，默认不交付完整答案 |
| 讲解式 `lecture` | 先解释数据、变量或算法，再让学生修改当前项目 |

### 4.3 不绕过PBL门禁

- 标准项目仍按现有9阶段推进。
- 复制项目的引导场景不能擅自调用 `stage_advancer` 快进。
- 一项改造任务完成，不等于整个PBL阶段完成。
- 任务结果使用现有证据系统记录，Skill阶段仍是项目主状态。
- 复制项目的轻项目初始化和代码权限应单独对齐，不能通过关闭全局门禁解决。

## 5. 完成式引导

“完成式”不是多一个完成按钮，而是系统必须验证学生的真实动作。

### 5.1 单任务结构

每项任务只包含：

```text
任务名称
学生要修改什么
完成条件
需要运行或检查什么
对应的一个知识点
```

首个样板任务建议：

| 次序 | 学生任务 | 验证 | 对应知识 |
|------|----------|------|----------|
| 1 | 替换标题和第一条内容 | 页面出现新内容 | 字符串、数据与页面 |
| 2 | 增加一条卡片数据 | 页面多出一张卡片 | 数组、重复渲染 |
| 3 | 修改一个交互或样式参数 | 点击/显示结果发生变化 | 事件或条件 |
| 4 | 制造并修复一次小错误 | 重新运行成功 | 报错、AI协作和核验 |
| 5 | 说明自己的改动 | 形成证据和成果摘要 | 反思与表达 |

### 5.2 完成验证

学生点击QuestionCard中的“我改好了，请检查”后：

1. AI重新读取已保存代码。
2. 使用 `code_runner` 或现有预览能力运行。
3. 根据任务完成条件检查结果。
4. 失败时只指出第一处关键问题，并提供一层提示。
5. 通过时调用现有证据工具保存“改了什么、怎样验证”。
6. 用1-3句话解释本次改动对应的编程、算法或AI知识。
7. 再询问是否进入下一项任务，不自动连续布置多个任务。

以下情况不能算完成：

- 学生只说“完成了”，但没有代码变化。
- AI生成了代码，但学生没有运行或检查。
- 页面运行失败。
- 验证标准要求出现新内容，但预览中没有出现。
- 学生无法指出自己改了哪一处，且没有形成任何过程证据。

## 6. 引导状态

MVP2不新增Tutor表或课程进度系统，只在现有Skill元数据增加一个小节点：

```json
{
  "copy_guidance": {
    "version": "1.0",
    "intro_status": "pending | dismissed | started",
    "session_status": "idle | active | waiting_verify | completed",
    "current_task": {
      "id": "replace_first_card",
      "title": "替换标题和第一张卡片",
      "acceptance_checks": ["code_changed", "run_success"]
    },
    "started_at": "2026-08-12T00:00:00Z",
    "updated_at": "2026-08-12T00:00:00Z"
  }
}
```

边界：

- 这里只保存首次提醒和当前一项任务的恢复信息。
- PBL阶段、工件、教学模式和证据仍保存在原有字段。
- 聊天历史仍是详细过程记录。
- 不建立播放进度、课程完成率或复杂学习画像。

## 7. 课程与短视频的触达

MVP2第一纵切先把任务引导跑通，不把课程库作为前置依赖。

任务引导和短视频的关系是：

```text
先给项目动作
-> 学生需要解释或连续失败
-> 推荐一条知识胶囊
-> 看完立即回到当前代码完成动作
```

首个样板的5条视频仍按以下职责规划：

| 视频 | 职责 | 在引导中的触发点 |
|------|------|------------------|
| V01 看懂项目成品 | 建立兴趣和目标 | Demo详情或第一次进入前 |
| V02 只改三处做成自己的版本 | 项目操作示范 | 学生不知道从哪里开始 |
| V03 数组怎样变成卡片 | 公共编程知识 | 增加或修改卡片数据时 |
| V04 让AI看懂第一条错误 | 公共AI素养 | 运行失败或主动询问时 |
| V05 怎样证明是自己完成的 | 证据和成果表达 | 任务通过、准备成果卡时 |

视频仍放在B站等第三方平台，fineSTEM只保存摘要和嵌入信息，不做播放率、完播率和外部账号联动。

## 8. 家长可理解功能

MVP2不新建家长工作台，也不要求家长学习编程。

复用现有项目详情和成果档案卡，补足以下非技术信息：

- 孩子从哪个Demo开始。
- 孩子自己修改了什么。
- 孩子运行或验证了什么。
- 孩子能够解释的一个知识点。
- AI提供了什么帮助。
- 哪些内容是AI生成，哪些决定和改动由孩子完成。

家长摘要必须来自代码变化、运行结果、对话和证据，不得只根据AI话术推断孩子已经掌握某项能力。

## 10. 推荐开发顺序

```text
先验证并修复Demo代码复制
-> 对齐复制项目Skill初始化
-> 做首次提醒和任务引导入口
-> 接入AI读代码与单任务输出
-> 接入运行验证和证据保存
-> 配置首个样板任务
-> 再接入5条视频和家长摘要
```

不要先做悬浮动画、语音、课程后台或复杂任务看板。这些都不能解决“孩子复制项目后不知道第一步做什么、做完也无法证明”的核心问题。

## 11. MVP2验收标准

- [ ] 从Demo保存项目后，Create恢复的是该Demo的真实代码，而不是空工作区或默认模板。
- [ ] 只有 `from_demo_id` 非空的项目出现首次提醒和任务引导入口。
- [ ] 自己创建的项目完全不受影响。
- [ ] 首次提醒只显示一次，换设备后也不重复。
- [ ] 未点击“开始任务引导”时，不自动发送AI消息。
- [ ] 点击开始后，AI先读取Skill状态和真实代码。
- [ ] AI一次只给一项任务、一个完成条件和一个下一步动作。
- [ ] 四种现有教学模式继续有效，不新增第五套导师模式。
- [ ] 学生说完成后必须经过代码读取和运行/预览验证。
- [ ] 验证失败只处理第一处关键问题。
- [ ] 验证通过后形成一条真实证据，并可进入下一任务。
- [ ] 标准PBL项目的阶段门禁没有被复制项目逻辑破坏。
- [ ] 现有项目恢复、聊天、代码保存、运行、讲解和成果卡没有回归。
- [ ] 数字人和语音不作为MVP2完成条件。

## 12. MVP2完成定义

> 一个孩子把Demo保存为自己的项目后，不需要先学会怎样向AI提问；他可以从一次性提醒或任务引导入口开始，在现有Skill和教学模式帮助下，完成至少一次真实修改、一次运行验证、一次知识解释和一条可供家长理解的成果证据。

这就是MVP2的最小闭环。它不是新页面，也不是第二套导师系统，而是把现有Demo、Create、Skill、代码运行和成果卡真正串成一次可完成的学习行动。
