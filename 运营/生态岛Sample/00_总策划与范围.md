# 生态岛 Sample：总策划与范围
日期：2026-11-02｜状态：可分派的制作规划，尚未执行开发与发布。

## 1. 产品定位

一个主题sample＝可玩的作品＋领域知识内容＋自助创作路径＋完整过程档案＋家长视频与博客。

fineSTEM是制作和文档工具：孩子创建/复刻项目、看代码、运行、修改、产生文档。已有Agent也可作为替代制作入口。丰富的科学内容、学习引导和延伸阅读由Know及配套内容承载；本项目不要求fineSTEM新增复杂教学或项目管理系统。

单人、线上、自助；不依赖硬件、实体实验、团队、线下观察或家长协作。受众为小学到高中，平均以 6 年级-高一为主（约 11-16 岁）；零基础至初级编程。2026-11-03 统筹拍板。

## 2. 第一套作品

题目暂定《生态岛：小岛为什么变了？》。
孩子看到草、抽象食草动物与资源状态随模拟步变化，能调整初始条件和一种资源补充设置，观察并解释结果，然后复刻或改造一条规则。

核心学习问题：改变一个条件，哪些状态会跟着变化？为什么？这种解释适用于什么范围？

### P0：首版必须完成

- 一个二维岛屿示意，清楚区分草、动物、资源。采用CSS/SVG/Canvas即可，不依赖AI生成图片。
- 三个状态：草量指数、食草动物种群指数、可用水分/资源指数；具体名称、范围、规则由科学与模型Agent确定并写明。
- 开始、暂停、单步、重置；显示模拟步数、当前状态和简洁的变化记录。
- 初始配置可调；一种环境设置，例如资源补充档位。
- 同样输入可重现；所有更新均来自明确规则；结果与画面对应。
- 一份运行说明和模型限制说明。
- 完整参考代码、可运行起始代码、三个关键检查点。
- 至少一个规则改造任务，能比较原版与修改版。
- 知识、引导、作者真实档案、文档模板、家长视频和博客。
- 通过实际运行入口验证的操作说明及Know待发布内容包。

### P1：P0完成后再决定

下载试验记录、配置保存、对照图、多事件、声音、额外视觉表现。只有确实改善探索或复现体验才增加。

### 当前不做

多物种食物网、个体寻路、三维场景、物理引擎、实时天气、传感器、后台数据库、新账户系统、自动评分、完整课程系统、完整任务看板产品、实时Agent编排平台。少量任务清单和引导文档即可承担项目管理教学。

## 3. 用户路径与内容分工

1. 在Know玩完整作品，提出疑问。
2. 看知识解释与作者开题，理解作品的目标和简化。
3. 选择“复刻这个项目”，按已经验证的路径进入fineSTEM或已有Agent。
4. 分步构建、解释代码、测试和记录。
5. 选择一项变化，写简单计划并改造。
6. 用作品、过程文档和报告说明“我做了什么、为什么这样做、学到了什么”。

不准备做项目的读者可以停留在试玩与科普。家长视频和博客独立可读，不以家长全程陪伴为前提。

| 能力 | 在本项目中的最低证据 |
|---|---|
| 编程 | 解释状态、条件、函数或事件中的一段关键逻辑，并改动验证 |
| 算法 | 手推一次状态更新，理解先后顺序与边界 |
| 项目管理 | 写目标、拆至少三个任务、记录一个问题和一次变更 |
| 领域知识 | 解释资源限制或生态关系，指出教学模型的一项省略 |
| 文档表达 | 从开题到结果可追溯，能用作品和报告进行简短汇报 |

## 4. 内容交付

- 少年领域内容：3–4篇短章节，围绕关系、资源、时间过程和模型边界。
- 作品拆解：数据是什么、规则怎样写、程序怎样推进、界面怎样表现。
- 复刻路线：三个关键检查点＋任务卡、提示、自查、常见错误。
- 改造路线：入门参数比较＋标准规则改造；进阶方向仅提供思路。
- 文档：作者实际制作档案、孩子空模板、真实证据支持的示范报告、汇报提纲。
- 家长内容：约90–120秒短视频脚本及成片，一篇建议1200–1800字博客；实际长度服从表达。
- 少年操作讲解：建议4–6分钟真实录屏，具体时长在样片验证后调整。
- Know：内容描述、知识与资料入口、视频、互动和真实项目入口。

“完整六件套可发布”与“作品内部预览”分开验收。缺少视频或博客可以内部验证作品，但不能声称整套sample已经完成。

## 5. 团队分块

| 工作包 | 责任 | 输出目录 |
|---|---|---|
| A 科学与模型 | 知识来源、简化规则、解释边界、已知测试用例 | 交付/A_科学模型 |
| B 作品开发 | 小型网页、代码版本、检查点、实际运行证据 | 交付/B_作品代码 |
| C 学习引导 | 知识章节、复刻改造、代码算法、助教任务卡 | 交付/C_学习引导 |
| D 文档汇报 | 作者档案整理、孩子模板、报告和汇报材料 | 交付/D_文档汇报 |
| E 家长内容 | 博客、视频稿、分镜简报及来源口径 | 交付/E_家长内容 |
| F 媒体制作 | 实际录屏、配音/字幕、成片、封面、媒体清单 | 交付/F_媒体制作 |
| G 平台接入与验收 | 早期能力验证、晚期整合验收、Know待发布包 | 交付/G_接入验收 |

这是供用户分派的七个工作包，不自动创建或派出Agent。可由不同Agent完成，也可按能力合并执行。

## 6. 工程与平台原则

优先普通HTML/CSS/JavaScript、少依赖。开发源代码可适度拆文件，交付尽量提供一个方便导入的index.html；实际形式由G的早期能力验证决定。网页不承载整套课程或全部家长内容。

所有科学主张先由A确认。代码实现不能为戏剧性编造模型效果；文案不能先写结果，再要求代码凑结果。参考模型、代码、引导和视频必须对应同一冻结版本。

平台能力限制优先用缩小作品、手工导入和文档引导解决。需要修改fineSTEM核心能力时单列后续需求，不拖入本sample。

## 7. 完成定义

用户能从Know发现并玩到作品，读懂必要知识，依据指南在已验证的制作入口复刻和改造，保存相关文档，并有可展示作品与可汇报材料。制作团队提供完整、真实、版本对应的六件套。

本规划未创建生产项目、账号、部署、公开视频或新系统。全部Agent交付到G盘项目目录。
