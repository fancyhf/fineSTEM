## 1. 字段规范

### 1.1 状态对象 state（stepModel 的输入与输出同构）

| 字段 | 类型 | 范围 | 含义与口径 |
|---|---|---|---|
| `step` | 整数 | ≥ 0 | 模拟步计数。**模拟步是离散计算步，不是真实天数**，任何文案不得写成"第 N 天" |
| `grass` | 浮点（存储时保留两位小数） | ≥ 0；**模型层无上限截断**（可超过 100） | 草量指数。**教学指数，不是真实公斤/株数** |
| `herbivores` | 整数（存储时取整） | [0, 100]（截断） | 食草动物种群指数。**教学指数，不是真实只数** |
| `water` | 浮点（存储时保留两位小数） | [0, 100]（截断） | 可用水分指数。**教学指数，不是真实升/毫米降雨** |

### 1.2 配置对象 config

| 字段 | 值 | 说明 |
|---|---|---|
| `modelVersion` | `"eco-island-v1"` | 与本文件冻结版本一致的标签 |
| `initialState` | `{ grass, herbivores, water }` | v3 界面默认值：草 60、动物 20、水 50（滑杆范围 0–100，重置后生效） |
| `environment.replenishLevel` | `"low"` \| `"mid"` \| `"high"` | 补充档位。**键名注意：是 `mid` 不是 `medium`**（见 §6.3） |
| `maxSteps` | 60（v3 常量 `MAX_STEPS`） | **模型层不读取此字段**；它只在界面层使用（见 §6.2） |

### 1.3 核心函数签名

```js
stepModel(previousState, config) -> newState
```

要求（公共约定 §4）：确定性；不修改 `previousState`；边界与顺序固定；显示与模型分离。

## 2. stepModel 逐字源码（冻结，摘自权威实现）

```js
function stepModel(previousState, config) {
  const { step, grass, herbivores, water } = previousState;
  const { environment } = config;
  let newGrass = grass;
  if (water > 0) {
    if (grass < 80) { newGrass = grass + 2; } else { newGrass = grass + 0.5; }
  }
  const eaten = herbivores * 0.8;
  newGrass = Math.max(0, newGrass - eaten);
  let newHerbivores = herbivores;
  if (newGrass > 50) { newHerbivores = herbivores + 2; }
  else if (newGrass < 20) { newHerbivores = herbivores - 3; }
  newHerbivores = Math.max(0, Math.min(100, newHerbivores));
  const replenishSpeed = { low: 1, mid: 3, high: 6 }[environment.replenishLevel] || 3;
  let newWater = water + replenishSpeed - (herbivores * 0.3);
  newWater = Math.max(0, Math.min(100, newWater));
  return {
    step: step + 1,
    grass: Math.round(newGrass * 100) / 100,
    herbivores: Math.round(newHerbivores),
    water: Math.round(newWater * 100) / 100
  };
}
```

（同文件中还有 `clamp100(x) = Math.max(0, Math.min(100, x))` 辅助函数，stepModel 内部未直接调用它，而是内联展开。）

## 3. 更新顺序与公式（人读版，顺序即执行顺序）

每一步**只使用旧状态（previousState）的值**来计算，四个子步骤依次为：

**① 草生长**（用旧 `water`、旧 `grass`）

- 若 `water > 0`：`grass < 80` 时 `+2`；`grass >= 80` 时 `+0.5`（草密长得慢）
- 若 `water = 0`：不长（干旱）

**② 动物吃草**（用旧 `herbivores`）

- `eaten = herbivores × 0.8`
- `newGrass = max(0, 生长后草量 − eaten)`（草不为负）

**③ 动物增减**（用②**之后**的 `newGrass` 判断，不是旧草量）

- `newGrass > 50` → `+2`（草多，迁入/繁衍；**从 0 也能 +2 迁入**，见 §6.4）
- `newGrass < 20` → `−3`（草少，饿走）
- `20 ≤ newGrass ≤ 50` → 不变
- 结果截断到 [0, 100]

**④ 水更新**（用旧 `herbivores` 扣水；档位查表）

- `replenishSpeed = {low:1, mid:3, high:6}[replenishLevel] || 3`（未知档位回退为 3）
- `newWater = clamp(旧 water + replenishSpeed − 旧 herbivores × 0.3, 0, 100)`

**返回**：`step + 1`；`grass`、`water` 四舍五入两位小数；`herbivores` 四舍五入到整数。

顺序要点（B 实现与 C 讲解时的检查锚点）：
1. 草生长判断用的是**旧水**；同一步加水不会让本步的草生长受益。
2. 动物增减判断用的是**吃过之后的草**；本步吃得多，可能立刻触发减员。
3. 扣水用的是**旧动物数**；本步动物增减不影响本步耗水。
4. 每步返回值先舍入再存入下一步；**下一步以上一步舍入后的值为输入**（长链计算与"不舍入连算"会有微小差异，以本规范含舍入的链为准）。

## 4. 取整规则

| 字段 | 规则 | 实现 |
|---|---|---|
| grass | 保留两位小数 | `Math.round(x * 100) / 100` |
| herbivores | 取整（四舍五入） | `Math.round(x)` |
| water | 保留两位小数 | `Math.round(x * 100) / 100` |
| step | 精确 +1 | — |

由于增减量固定为 2/3 与 0.8×整数、0.3×整数，正常使用（初始值为整数）时 herbivores 始终为整数、grass/water 最多两位小数（例：TC07 水 `66.66+1−13×0.3=63.76`）。

## 5. 确定性声明（已实测验证）

1. **无随机数**：stepModel 不使用 `Math.random()`，同输入永远同输出。
2. **重复运行一致**：默认配置 60 步两次运行轨迹逐字段完全一致（test-cases.json TC09，A-E001）。
3. **不修改旧状态**：调用 stepModel 后 `previousState` 逐字段不变（A-E001 purityCheck 实测）。
4. **显示与模型分离**：v3 的 `render(state)` 只读状态画画面（花、兔子数、池塘高度均由状态确定性推导）；开始/暂停/三档速度只改变播放间隔，不改变任何一步的计算结果（SPEED 常量只用于 `setInterval`）。
5. **改配置的固定行为（v3 界面层）**：初始条件（三个滑杆）只在【重来】后生效；下雨档位在暂停时可改、跑步中不可改（选择器回弹）。B 若改此行为，须同步改 C/F/G 的说明。

## 6. 边界行为（如实记录，含与旧实现的差异）

### 6.1 值域边界

- `herbivores`：截断到 [0,100]，**不会为负**（0 再减 3 仍是 0）。
- `water`：截断到 [0,100]。
- `grass`：只有下限 0（`max(0, …)`），**没有上限截断**（代码事实）。TC05（草100/动物100/大雨）吃草前中间值为 100.5；A-E002 探针 S-G（初始草 100 / 动物 0 / 水 50 / mid）显示**存储状态可超过 100**：第 1 步草 = 100.5（动物 0→2 迁入），第 2 步起被啃回落回 99.4——但由于"草>50→动物+2 迁入"规则，草并不会长期滞留在 100 以上（S-G 第 60 步草 = 21.2）。
  - 对下游的含义：渲染层不要假设 grass ≤ 100；进度条等显示需自行封顶（v3 直接用 `state.grass + "%"`，超 100 时进度条视觉封顶但数值会显示 >100，B 复核时留意）。

### 6.2 maxSteps 停机边界：**不在模型层**

- **冻结的 stepModel 不检查 maxSteps**：即使 `step >= maxSteps`，调用 stepModel 仍返回 `step+1` 并正常更新（test-cases.json TC10 实测：`step=3, maxSteps=3` 时返回 `step=4` 且草/水照常更新）。
- v3 界面层的停机策略：自动运行到 `step >= 60` 即暂停；开始按钮在 `step >= 60` 时拒绝启动；**单步按钮未拦截**（v3 里 60 步后仍可手动单步越过 60）。B 应决定是否在单步处也拦截，并告知 C/F/G（见 HANDOFF 变更建议 #2）。
- `maxSteps` 仅在界面层读取；把 config.maxSteps 传给 stepModel 是无害的，但模型不使用它。

### 6.3 与同目录旧实现的差异（重要：版本卫生问题）

A 包于 2026-11-03 对 `范本_fineSTEM制作/code/` 下四个文件的 stepModel 做了剥注释逐字比对（证据 A-E001 crossVersionComparison）：

| 文件 | 与 v3 的差异 |
|---|---|
| `eco-island-ai-chat-v1.html`（v1） | 逻辑等价，仅两处非语义差异：内部注释多；档位键名用 `"medium"`（v3 用 `"mid"`）。因有 `\|\| 3` 回退，用 `"mid"` 调 v1 数值上碰巧也是 +3，但**键名契约不同** |
| `eco-island-ai-chat-v2.html`（v2） | 同 v1 |
| `eco-island-reference.html`（参考版） | **实质不同**（见下表） |

reference.html 的 stepModel 与冻结模型的 4 处实质差异：

1. **模型层有 maxSteps 停机**：`if (previous.step >= config.maxSteps) return {…不变…}` ——任务描述中"step>=maxSteps 时状态不变"的出处是这一旧实现，**不适用于冻结的 v3/kids 版**。
2. 补水用 `config.environment.replenishRate`（数值），不是档位查表。
3. 草值 `Math.round(clamp100(grass) * 10) / 10`：有上限截断、一位小数。
4. 动物值 `Math.round(herbivores * 10) / 10`：一位小数，不是取整。

**风险**：reference.html 的文件头同样写着 `MODEL_VERSION = "eco-island-v1"`，即同一个版本标签目前对应两种行为。处置建议见 HANDOFF 变更建议 #1。B/G 引用模型时必须认准 kids-v3 的实现；不得把 reference 的行为当成 eco-island-v1 的行为。

### 6.4 教学上需要明说的模型事实（文案口径见 §9）

- **草 > 50 时动物从 0 也能 +2**：规则不区分"繁殖"和"从岛外迁入"，0 不是吸收态。教学口径：岛是开放的，动物可以回来（教学设定，简化）。
- **加水档位调高不能拯救动物**：默认参数下动物啃食 16/步，草生长上限 +2/步（<80 时），水资源只决定"草能不能长"，不决定"长多快"（生长速率恒为 2 或 0.5）。低/中/大雨三档实测：动物都在第 9 步归零、第 34 步回增（A-E002 S-A/S-B/S-C）。
- **动物归零不等于失败**：h=0 后草与水自动恢复，且草过 50 动物还会迁回来（TC08、A-E002 S-A/S-E）。

## 9. 下游引用口径（可直接照抄的句子）

- "三个数字（草、动物、水）是 0–100 的教学指数，不是真实的草公斤数、动物只数或水量。"
- "一步是一次计算更新，不是一天。"
- "同样的开局和设置，每一次运行的结果完全一样——模型里没有骰子。"
- "动物归零说明这一局里动物离开/消失了；草和水会自己恢复，动物也可能再迁回来，这不代表小岛'死了'。"
- "多下雨让水位更高，但没有让动物活下来——因为限制它们的是草的生长速度，不是水。"（默认参数下成立，勿推广为无条件结论）
- 禁止的写法："第 N 天""真实的兔子数量""降雨量 X 毫米""加水一定更好""动物灭绝=生态毁灭""模型预测真实生态"。

## 10. 模型未包含的内容（解释适用范围，供 C/E 引用）

捕食者与食物网；个体繁殖/死亡/年龄；疾病；季节与天气随机性；土壤与养分循环；空间分布与寻路；种内差异与遗传；多物种竞争；人类活动；真实单位换算。模型回答的是"**改变一个条件，哪些状态跟着变、为什么**"，不回答"真实小岛会怎样"。
