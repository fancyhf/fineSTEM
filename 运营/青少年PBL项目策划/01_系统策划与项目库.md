# 青少年 PBL 项目系统策划

> V1历史方案：主方向已由[V3线上自助Sample体系](07_V3_线上自助Sample体系.md)替代。本文件保留为小项目与工具练习资源。

日期：2026-10-19｜v1.0｜供课程设计、产品和内容运营共同使用。

## 1. 要做成什么

建议用“少年研究所”作为活动名称候选，以“一个问题，一件作品，一份有依据的解释”为项目统一交付口径。名称可调整，项目结构保持一致。

孩子经历的路径是：**看见现象 → 提出自己的问题 → 学必要知识 → 设计办法 → 用 fineSTEM 编程 → 测试与改进 → 用证据解释 → 向真实观众展示。**

| 载体 | 主要任务 | 本轮交付 |
|---|---|---|
| 鸡娃先自鸡 | 让家长理解这个问题值得研究什么、怎样陪伴、怎样判断孩子学到了 | 家长主题内容、家庭对话卡、陪伴边界 |
| Know | 帮家庭发现和选择项目，承接试玩、讲解和任务资料 | 项目介绍、少年任务讲解、资料包、fineSTEM 项目入口 |
| fineSTEM | 让孩子亲自完成问题定义、代码制作、验证和解释 | 项目工作区、代码版本、过程证据、成果与文档 |

家长内容讨论“这件事怎么看”，少年内容帮助孩子“这件事怎样研究”。运营使用实际项目中的问题和证据，但两种受众分别组织讲法和演示。

## 2. 项目的统一设计法

每个项目必须明确以下八项，缺一项就暂不进入制作。

| 项目要素 | 设计要求 | 排队侦探举例 |
|---|---|---|
| 驱动问题 | 孩子能理解，允许提出不同方案 | 同样两个窗口，共享队伍一定等得更少吗？ |
| 领域与知识 | 1 个主领域，2–3 个本次必须学会的概念 | 服务系统；等待时间、离散事件、比较实验 |
| 学生选择 | 至少一个会影响结果的真实决定 | 选场景、选评价指标、提出一种队伍规则 |
| 可运行作品 | 能让别人操作或复核 | 队伍策略比较网页 |
| 编程目标 | 点名孩子要解释和修改的关键代码 | 数组、循环、函数、窗口可用时间 |
| 比较方法 | 先写条件和指标，再跑结果 | 两种策略使用相同到达/服务数据、相同窗口数 |
| 过程证据 | 每次活动留少量但有用的记录 | 假设、手算、版本、数据表、失败与修正 |
| 展示与改进 | 有外部反馈，学生回应并改一次 | 家长或另一组质疑“慢窗口怎么办”，学生补测 |

设计依据：PBLWorks 将有挑战的问题、持续探究、真实情境、学生选择、反思、反馈修订和公开成果列为项目设计要素。这里把它们转成上述可交付要求；展示可以是班级、家庭或受邀同伴，不要求儿童公开上网。[PBLWorks 官方设计框架](https://www.pblworks.org/gold-standard/pbl-project-design)

## 3. 学习分层与时间

| 层级 | 建议对象与前提 | 学习任务 | 产物与时间预算 |
|---|---|---|---|
| 体验 | 10–12 岁或首次接触；成人协助阅读 | 试玩、预测、改一个参数、解释变化 | 作品变体 + 一页发现卡；60–120 分钟 |
| 标准 | 主力 12–15 岁；会基本电脑操作，不要求先学语言 | 完整开题、分步制作、比较、迭代、答辩 | 6 次×60 分钟活动 + 观察/整理 1–2 小时 |
| 进阶 | 15–18 岁或已有基础；能解释基础代码 | 多场景、多次实验、敏感性分析或算法比较 | 研究短文及可复现附件；12–20 小时，另算观察周期 |

体验版是完整项目的入口，不据此宣称完成标准 PBL。标准版的报告建议 800–1500 字，进阶可扩为 1500–3000 字；这是表达负担的设计范围，不能用字数代替证据质量。植物等观察类项目可跨 1–2 周，主动操作时间和自然等待时间分开标明。

## 4. 候选项目库：领域、知识、代码、文档一一对应

下表均为待开发项目设计，不是已上线课程。代码中 JS 指 JavaScript；HTML/CSS 用于页面结构与样式，不当作与 JS 相同性质的编程语言。

| ID / 项目与驱动问题 | 领域与核心知识 | fineSTEM 作品与代码目标 | 方法及关键过程文档 | 建议层级 / 工时 | 家长内容切口 |
|---|---|---|---|---|---|
| P01 排队侦探：两条队还是共享队更省时间？ | 运筹与服务工程；先到先服务、平均/最长等待、资源约束 | JS 队伍模拟网页；数组对象、循环、函数、状态更新、输入校验 | 同数据比较两策略；开题、手算表、模型假设、实验表、修订日志、研究短文 | 标准；6–8h | 公平和效率怎么一起讨论 |
| P02 楼梯路线设计师：一步跨一阶或两阶，有几条路线？ | 数学建模；分情况、递推、初始条件 | JS 路线展示或 Python 计数；条件、循环、列表；递归仅进阶 | 小规模枚举核对递推，修改台阶规则；枚举草图、规则说明、边界测试、证明思路 | 体验→标准；2h / 6–8h | 从报答案转向解释规律；承接递推之美 |
| P03 文字接龙实验室：换一批文字，接出来的话会变吗？ | 语言与概率；相邻字频数、条件分布、抽样、样本偏差 | Python 字符级二元统计或 JS 本地展示；字典、计数、随机抽样、函数 | 固定两份自写短语料和生成长度，每组多次运行；语料卡、频数表、结果样本、局限说明 | 标准偏高；8–10h | 通顺为何不等于有事实依据；承接 AI 说话之谜 |
| P04 纸飞机试验员：哪种折法飞得更稳定？ | 飞行与实验设计；距离、离散程度、控制变量 | Python CSV 分析或 JS 记录面板；列表、平均、排序、绘图 | 同纸张/投掷者，交替测试折法；至少每种5次；测量规则、原始记录、异常说明 | 标准；6–8h | 为什么一次飞得远不能直接下结论 |
| P05 校园阴凉地图：更短和更阴凉怎样选？ | 地理与图论；节点边、路径、权重、取舍 | JS 简化虚构地图；对象、数组、路径求和；最短路算法进阶 | 固定观察时段，分别计距离与遮阴；地图图例、测量表、权重理由、路线比较 | 标准偏高；8–10h | 怎样把“更好”说成可以讨论的标准 |
| P06 阳台植物观察站：同一盆植物一天怎样变化？ | 植物观察与数据；测量、时间序列、混杂因素 | Python 折线图或 JS 观察日志；日期、缺失值、筛选、绘图 | 固定拍摄和测量位置，记录光照/浇水背景；观察协议、日志、缺测说明、发现卡 | 标准；6h操作+7–14天观察 | 连续观察和因果结论之间有什么距离 |
| P07 雨水收集设计师：同样降雨，不同屋顶能收多少水？ | 水循环与工程；面积、体积、单位换算、损耗假设 | JS 计算与方案比较器；变量、公式、函数、单位校验 | 用明确标注的假设降雨情景比较；单位推导、参数来源、容量表、设计说明 | 标准；6–8h | 数学怎样帮助家庭做实际判断 |
| P08 声音图案实验室：高低音和波形怎样对应？ | 声学；频率、周期、振幅 | JS 合成波形可视化；函数、数组采样、Canvas；音频为可选扩展 | 用合成信号逐项改参数；预测卡、波形图、参数表、解释短文 | 标准；6–8h | “听起来”与“测出来”怎么互相支持 |
| P09 像素压缩师：同一张图怎样存得更少？ | 数字图像与信息表示；像素、颜色编号、游程编码 | Python 编解码或 JS 像素编辑器；二维数组、循环、字符串、函数 | 用条纹、棋盘、随机三种合成图；编码协议、往返测试、长度比较表 | 标准；6–8h | 有些文件为什么越压越大 |
| P10 图表侦探：同一组数据为何看起来像两件事？ | 统计与媒介素养；轴范围、比例、样本量 | JS 图表对照器或 Python 绘图；数组、坐标映射、参数 | 同一固定数据仅改变呈现；数据来源、图表版本、误读说明、改进稿 | 体验→标准；2h / 6h | 家长和孩子一起识别图表表达的影响 |
| P11 生态平衡棋盘：局部规则会长出什么图案？ | 复杂系统；规则、邻域、时间步、模型局限 | JS 网格模拟；二维数组、嵌套循环、双缓冲 | 固定初态改一条规则；规则卡、初态快照、逐步记录、结果比较 | 进阶；10–12h | 看懂模拟能够回答什么；不把玩具规则称为真实生态预测 |
| P12 阅读推荐小助手：按什么标准推荐一本书？ | 信息检索与推荐；特征、加权评分、偏好、解释性 | Python 或 JS 规则推荐器；对象、筛选、加权和、排序 | 自建小书单，固定读者偏好比较权重；特征字典、评分依据、测试反馈 | 标准；6–8h | 机器推荐和自己的选择怎样配合 |

P03 的字符二元模型只展示“依据上下文频数选择下一个字”的局部机制，不能代替现代大语言模型的结构说明。P06 为观察研究，不据单盆结果宣称浇水或光照造成生长变化。P07 初版采用设定情景；若改为真实地区降雨，制作时补查原始数据来源和时间。

## 5. 先做哪几个

首批顺序建议为 P01 → P02 → P03。P01 完整验证研究流程，P02 与既有递推内容连接且能快速上手，P03 与正在策划的 AI 主题连接。P04、P07、P10 是第二批，分别补上实物实验、工程设计和数据表达。

这不是同一孩子必须依次完成的课程：没有代码基础的孩子可从 P02 体验进入；已经用 AI 写过程序的孩子可从 P01 标准项目进入；能理解字典与频数的孩子再选 P03。

选题取舍按五项检查：孩子能否观察或理解问题；核心知识是否能在限定课时讲清；能否形成可比较的证据；现有产品能否运行；是否与家长真实对话场景相连。纯粹更换界面、增加动画而没有新问题的题目，作为项目变体，不占新课程名额。

## 6. 每个项目怎么教：知识与代码绑定

采用“遇到问题再补知识”的短循环：**预测 → 小例子讲解 → 改一处代码 → 运行 → 解释差异 → 留一条证据**。每个循环约 10–15 分钟，单段知识讲解尽量控制在 5–8 分钟内；具体时长由试课调整。

| 编程层次 | 孩子必须完成的行为 | 适合的项目任务 |
|---|---|---|
| 数据与变量 | 说出一个值代表什么、单位是什么，改值并预测结果 | 排队的到达时刻、雨量、楼梯层数 |
| 判断与循环 | 能逐次追踪一个小例子 | 遍历客人、枚举路线、逐像素编码 |
| 函数与分解 | 解释输入、输出和职责，独立改一个规则 | 等待时间函数、颜色编码、评分函数 |
| 数据结构 | 解释为什么要用数组或对象，而非单个变量 | 客人列表、语料频数字典、地图 |
| 测试与调试 | 构造一个会失败的输入，提出并检验原因 | 空数据、负数、相同到达时间、单位混乱 |
| 数据表达 | 图表与原始数据对应；能解释指标局限 | 平均和最长等待、图表纵轴、结果分布 |

**语言是完成任务的工具。** 交互作品优先 HTML/CSS + JS；数据分析或文本实验可用 Python。一个标准项目只设一条主技术路线，另一种语言作为后续迁移挑战，避免为展示多语言而重复实现整套工程。

AI 可以解释报错、提供小段示例、协助页面样式和整理已存在的记录。每次提供关键逻辑前，先让孩子预测或描述规则；提供后让孩子逐步追踪、修改和验证。核心算法的选择、研究假设、结果解释由孩子完成。初学者可补全有 TODO 的骨架，进阶者自行实现。

“会了”的最小证据是：能解释输入输出；能预测改动；能改一条规则；能用例子验证。只要程序跑起来，仍不足以判定掌握。

## 7. 和当前产品能力怎么对接

以下是 2026-10-19 的本地源码观察，不代表生产环境已经逐项验收。

| 能力 | 本地依据 | 策划处理 |
|---|---|---|
| 标准九阶段及工件 | `apps/backend/app/services/stage_constants.py` | 沿用现有阶段和文件命名，见模板文件 |
| Python/JS 执行与 HTML 类模板 | `apps/backend/app/api/code_execution.py` | 首批以 JS 网页或 Python 脚本为主，上课前实际验证所选运行路径 |
| 证据与成果导出 | `apps/backend/app/services/document_service.py` | 现阶段保留人工整理完整附件的通道 |
| 自动文档正文 | 同上 `_build_markdown` | 当前证据摘要限制前50条、每条内容前120字符；尚不能据此认定研究报告内容完整 |
| Know 视频、文档、互动、项目资源 | `apps/backend/app/schemas/know.py` | 可用现有资源模型承接；课程专用字段暂无必要立即扩数据库 |

第一轮能用现有工作区完成制作，用本策划模板补齐记录和短文。后续优先提高证据可追溯与内容完整性，再优化版式。

## 8. 学习评价

下列评分是试点用内部量表，不是标准化能力测评。每项 0–3 分，总分 18 分；作品精美程度不单独计分。

| 维度 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| 问题与知识 | 无清楚问题 | 能复述题目 | 能解释关键概念 | 能将概念迁移到新场景 |
| 方案与代码 | 无法说明 | 知道页面功能 | 能追踪并修改核心逻辑 | 能独立提出并实现变体 |
| 实验与证据 | 无记录 | 仅有结果截图 | 条件、数据、版本齐全 | 有边界或反例，能复现 |
| 解释与局限 | 结论无依据 | 描述结果 | 结论对应证据 | 主动识别局限与替代解释 |
| 迭代 | 无修订 | 仅改外观 | 依据测试修复问题 | 依据反馈调整方案并复测 |
| 表达与协作 | 无讲解 | 读稿展示 | 自己讲清并回应问题 | 能帮助观众复核并吸收反馈 |

标准项目建议每项至少 2 分；不足部分明确补做动作，不用总分掩盖关键缺项。试课前后用相似但不完全相同的解释和改码任务对照，并记录 AI/成人帮助程度。

## 9. 扩充项目的生产模板

后续每个新题先填一页：项目ID；一句驱动问题；适龄与先备；主领域；三个知识目标；三个代码行为；作品最小范围；数据来源；比较方法；关键证据；学生选择；观众；工时与材料；家长话题；Know 资源；验收；能力依赖。

再制作：教师试做 → 手算或独立基准 → 学生骨架 → 教学问题卡 → 文档模板 → 小规模试课 → 修订 → 内容制作 → Know 发布。失败案例同样可以成为讲解素材，但必须标明实际发生的过程和结果。
